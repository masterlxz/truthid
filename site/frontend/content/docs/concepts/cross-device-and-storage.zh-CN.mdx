这里放在一起讲的是两个不同的问题，因为它们共享同一套底层传输方式：让您自己的一台设备与另一台设备通信（跨设备），以及让一份数据（密码库、一份文档）持久保存在某个永久的地方（存储）。

## 跨设备传输：局域网 + 离线中转 [#cross-device-transport-lan--dead-drop]

当移动端应用需要响应来自另一台设备的请求时 — 浏览器扩展拉取一个凭据，或另一台设备请求一个签名 — 它会**同时**使用两条通道，而不是一条作为另一条的后备：

- **局域网（快速路径）** — 响应方设备为这一次请求运行一个小型本地 HTTP 服务器，请求方在本地网络中扫描它。可用时速度很快，但需要两台设备处于同一网络且可互相访问 — 在某些网络（有客户端隔离的企业 Wi-Fi、某些 VPN 配置）或本地网络 API 受限的浏览器上，这会静默失败（具体例子见[浏览器扩展 → Brave](/docs/apps/extension#brave)）。
- **离线中转（尽力而为的后备方案）** — 同样的内容经过加密后推送到 IPFS，并以一个短期的 IPNS 名称（一个可变指针，不同于普通的 IPFS CID）发布，嵌入在请求方扫描的二维码中。由于它是并行运行，而不是只在局域网超时之后才启动，哪条通道先响应就用哪条 — 您不需要等完整的局域网超时才会回退。

即使在密码库自身的永久存储迁移到 Arweave 之后（见下文），离线中转仍然刻意继续使用 IPFS/IPNS — Arweave 没有可变、短 TTL 指针这个概念，而这恰恰是一次性临时交接所需要的东西，普通的 IPFS CID 同样也无法就地更新。不同的任务，用不同的工具，这是刻意为之的。

## 委托签名（包括第三方应用） [#delegated-signing-including-third-party-apps]

一台设备 — 桌面端或移动端 — 可以代表另一方执行一次请求，而对方永远不会持有您的密钥：

- **签名一条消息** — 用设备密钥对任意数据签名，不产生链上影响。
- **签名并执行** — 签名*并且*通过 bundler 提交一笔 `UserOperation`，由智能账户完成，产生实际的链上操作。
- **固定**（`POST /truthid/v1/pin`）— 让第三方应用使用您已经配置好的存储永久发布内容，而无需该应用自己搭建存储/固定服务。这是面向您使用的其他应用的 — 它们想以您的身份，而不是它们自己的基础设施，代您存储一些东西。

这三种操作在任何事情发生之前，都会显示一个批准界面，说明是哪个应用在发起请求 — 与登录时的 origin 校验是同样的原则（见 [TruthID 工作原理 → 登录](/docs/concepts/how-it-works#logging-in)）。桌面端和移动端上的每一个请求都会单独获得批准 — 不存在持久的按应用授权或配额，能让一个受信任的应用在后续调用中跳过提示。

出于对已经接入该路由的应用的向后兼容考虑，这条路由仍然叫 `/truthid/v1/pin`，响应中的字段仍然叫 `cid` — 但在下面的 Arweave 迁移之后，实际发布的目标是 Arweave，而不是 IPFS。不要按字面意思理解这个名字。

## 永久存储：Arweave

密码库的加密数据块以及其中的任何文档，都需要存放在某个不依赖任何一台设备保持在线的永久位置。以前是 IPFS（通过一个固定服务），现在是 Arweave — 一个一次付费、永久存储的网络，通过一个手写客户端（不依赖任何第三方 SDK）访问，桌面端（Rust）和移动端（Dart）应用都实现了同一套通信协议。

`VaultRegistry` 的链上指针字段现在字面上仍然叫 `cid`（见[智能合约 → VaultRegistry](/docs/contracts#vaultregistry)）— 这是它曾经只存放 IPFS CID 那个时代遗留下来的名字。迁移之后，新发布的密码库的 `cid` 值会变成类似 `ar://<arweave-transaction-id>` 的形式；两个应用都会检查这个前缀，如果看到就从 Arweave 网关获取，对于旧密码库可能仍保留的纯 CID 格式，则回退到 IPFS 网关。

<Callout title="已知的注意事项：旧密码库与新设备的加入" type="warn">
一个身份的密码库，如果自 Arweave 迁移以来还没有*重新发布*过，就仍然指向它旧的 IPFS CID — 而曾经让旧 CID 保持可访问的专用固定基础设施已经下线，因此把一台全新设备与该身份配对时，可能会因为无法获取密码库而失败（公共 IPFS 网关对未固定的内容会超时）。这不是数据丢失 — 任何已经缓存过密码库的设备仍然拥有它 — 但目前还没有自动回退机制。如果您正在配对一台新设备，但找不到您的密码库，请先从一台已经拥有它的设备发布一次更新（任何密码库编辑都会重新发布到 Arweave），然后再重试配对。
</Callout>
