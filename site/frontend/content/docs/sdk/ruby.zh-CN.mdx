RubyGems 上 [`truthid-sdk`](https://rubygems.org/gems/truthid-sdk) 的完整 API 参考。刚接触 TruthID？请先看[快速开始](/docs/quickstart) — 本页是您正式集成时，每一个方法和类型的详细参考。

## 安装

```bash
gem install truthid-sdk
```

需要 Ruby 3.0+。

## `TruthID::Client`

```ruby
require "truthid"

truthid = TruthID::Client.new  # defaults to network: "base-mainnet"
```

如果您更喜欢，也可以用一个工厂函数：

```ruby
truthid = TruthID.new_client  # equivalent to TruthID::Client.new
```

### 构造函数

`TruthID::Client.new(network: "base-mainnet", rpc_url: nil)`

| 字段 | 类型 | 是否必需 | 说明 |
|-------|------|----------|--------------|
| `network` | `"base-sepolia"` 或 `"base-mainnet"` | 否 — 默认为 `"base-mainnet"` | 从哪个网络读取合约 |
| `rpc_url` | `String` 或 `nil` | 否 | 自定义 RPC 端点。默认使用所选网络的公共 Base RPC |

与 Python 一样，这里的 `network` 有默认值 — 只有需要覆盖它或使用测试网时才需要传入。（TypeScript SDK 则要求显式传入，没有默认值。）

## 方法

### `create_challenge(origin)`

创建一个一次性挑战，嵌入展示给用户的二维码中。

**参数**

| 名称 | 类型 | 说明 |
|------|------|-------------|
| `origin` | `String` | 您站点的域名，例如 `"yoursite.com"` |

**返回** [`AuthChallenge`](#authchallenge)

```ruby
challenge = truthid.create_challenge("yoursite.com")
challenge.nonce      #=> "3f2e1a4b-..."
challenge.issued_at  #=> 1718000000000
```

<Callout title="先存储，再删除" type="idea">
把挑战保存在服务端，以 `nonce` 为键，直到 `verify_auth_response` 运行为止 — 然后立即删除它。见下方的 [Nonce 失效处理](#nonce-失效处理)。
</Callout>

**构建二维码** — 移动端应用要求这个精确的结构（`challenge.to_h` 已经产生了正确的驼峰命名键）：

```json
{
  "action": "truthid-auth",
  "challenge": { "type": "challenge", "nonce": "...", "issuedAt": 1718000000000, "origin": "yoursite.com" },
  "callbackUrl": "https://yoursite.com/auth/verify"
}
```

`callbackUrl` **必须**使用 `https://` — 移动端应用拒绝把已签名的响应发到明文 `http://` URL。

### `verify_auth_response(challenge, response, ttl_ms: 30_000)`

验证从用户手机收到的已签名响应。依次运行六项检查，在第一次失败时停止：

1. 用户已批准（未拒绝）
2. 挑战在 TTL 之内（默认：30 秒）
3. Nonce 与原始挑战匹配
4. 密码学签名有效
5. 设备已在区块链上注册且处于活跃状态
6. 获取与该设备关联的身份 ID

**参数**

| 名称 | 类型 | 说明 |
|------|------|-------------|
| `challenge` | [`AuthChallenge`](#authchallenge) | 您创建的挑战 |
| `response` | [`AuthResponse`](#authresponse) | 从手机收到的响应 |
| `ttl_ms:`（可选） | `Integer` | 挑战的最大存活时间（毫秒）。默认：`30_000` |

**返回** [`VerifyAuthResult`](#verifyauthresult)

`AuthResponse.from_hash` 可以直接从解析后的 JSON 请求体构建 — 与 Python SDK 不同，不需要手动做字段映射：

```ruby
data = JSON.parse(request.body.read)  # { "approved" => ..., "nonce" => ..., "signature" => ..., "deviceAddress" => ... }

response = TruthID::AuthResponse.from_hash(data)
result = truthid.verify_auth_response(challenge, response)

if result.valid
  puts "Authenticated! Identity ID: #{result.identity_id}"
else
  puts "Failed: #{result.reason}"
end
```

**失败原因**

| `reason` | 原因 |
|----------|-------|
| `"User rejected the login request"` | 用户在手机上点击了"拒绝" |
| `"Challenge expired"` | 自 `issued_at` 起，经过的时间超过了 `ttl_ms` 毫秒 |
| `"Nonce mismatch"` | 响应的 nonce 与挑战的不匹配 |
| `"Invalid signature format"` | 签名格式不正确 |
| `"Signature does not match device address"` | 签名不是由 `device_address` 做出的 |
| `"Device is not active or has been revoked"` | 该设备已被身份所有者撤销 |

### `verify_session(session_hash)` [#verify_sessionsession_hash]

检查一个会话哈希是否仍然有效（未被撤销）。在登录后的后续请求中调用它，以确认会话没有从另一台设备被撤销。

**参数**

| 名称 | 类型 | 说明 |
|------|------|-------------|
| `session_hash` | `String` | `bytes32` 十六进制字符串（`0x...`） |

**返回** [`SessionInfo`](#sessioninfo)

```ruby
session = truthid.verify_session(session_hash)
if session.exists && !session.revoked
  # still logged in
end
```

---

### `check_device_status(device_pub_key)`

在区块链上查询一台设备的当前状态。

**参数**

| 名称 | 类型 | 说明 |
|------|------|-------------|
| `device_pub_key` | `String` | 该设备的以太坊地址（`0x...`） |

**返回** [`DeviceStatus`](#devicestatus)

```ruby
status = truthid.check_device_status(device_pub_key)
```

### `compute_smart_account_address(ledger_address, index: 0)` [#compute_smart_account_addressledger_address-index-0]

通过 `CREATE2` 预测用户的智能账户（控制方）地址 — 纯本地计算，不需要 RPC 调用，也不涉及服务器。适用于在账户从未上链使用过之前，展示一个存款地址或查询余额。

**参数**

| 名称 | 类型 | 说明 |
|------|------|-------------|
| `ledger_address` | `String` | 拥有该账户的硬件钱包/EOA 地址 |
| `index:`（可选） | `Integer` | 账户索引，用于每个所有者拥有多个智能账户的情况。默认：`0` |

**返回** `String` — 带校验和的智能账户地址。

```ruby
smart_account = truthid.compute_smart_account_address(ledger_address)
```

当您不需要完整的客户端实例时，也提供了一个模块级函数：

```ruby
smart_account = TruthID.compute_smart_account_address(ledger_address, network: "base-mainnet")
```

## 类型

以下全部都在 `TruthID` 模块中。`AuthChallenge` 和 `AuthResponse` 是普通类 — 它们的属性遵循正常的 Ruby 蛇形命名（`issued_at`、`device_address`），并各自在与移动端应用实际发送和签名的驼峰命名 JSON 交界处，提供一个转换方法（`to_h` / `from_hash`）。`VerifyAuthResult`、`SessionInfo` 和 `DeviceStatus` 是 `Struct`，因为它们从不跨越网络边界。

#### `AuthChallenge` [#authchallenge]

```ruby
class AuthChallenge
  attr_reader :type, :nonce, :issued_at, :origin

  # to_h => { "type" => ..., "nonce" => ..., "issuedAt" => ..., "origin" => ... }
end
```

#### `AuthResponse` [#authresponse]

```ruby
class AuthResponse
  attr_reader :approved, :nonce, :signature, :device_address, :session_signature

  # self.from_hash(h) reads h["deviceAddress"] into device_address, etc.
  # session_signature: personal_sign over keccak256(nonce) — always sent alongside signature
end
```

#### `VerifyAuthResult` [#verifyauthresult]

```ruby
VerifyAuthResult = Struct.new(:valid, :identity_id, :device_address, :reason, keyword_init: true)
```

#### `SessionInfo` [#sessioninfo]

```ruby
SessionInfo = Struct.new(:exists, :revoked, :identity_id, :device_pub_key, :created_at, keyword_init: true)
```

#### `DeviceStatus` [#devicestatus]

```ruby
DeviceStatus = Struct.new(:exists, :active, :label, :identity_id, :added_at, keyword_init: true)
```

## 安全说明

### Nonce 失效处理 [#nonce-invalidation]

在调用 `verify_auth_response` **之前**从您的存储中删除挑战，而不是之后 — 之后再删除会留下一个竞态条件，让同一个已签名的响应可以在 TTL 窗口内被提交两次。

```ruby
# Correct order
pending_challenges.delete(response.nonce)            # delete first
result = truthid.verify_auth_response(challenge, response)  # then verify
```

### TTL

默认值是 30 秒，与移动端应用自身的挑战过期时间一致。调低它没问题；调高到超过 30 秒不会有任何效果，因为手机本来就会拒绝一个更旧的挑战。

### 仅限 HTTPS

手机把已签名的响应直接 `POST` 到您的回调 URL — 移动端应用拒绝非 `https://` 的 URL，而且您的端点仍然需要一份有效的 TLS 证书才能连接成功。

## 会话可见性 — 无需额外操作

已完成的登录会自动出现在用户的 TruthID 移动端/桌面端应用中，并可以从那里单独撤销。手机会在调用您的回调 URL 之前，自行在链上注册会话（通过一笔 UserOperation）— 没有需要您额外调用的单独注册步骤。

如果您想再次确认某个会话确实上链，可以从 nonce 推导出它的哈希，并调用 `verify_session`：

```ruby
session_hash = "0x" + Eth::Util.keccak256(response.nonce).unpack1("H*")
session = truthid.verify_session(session_hash)
if session.exists && !session.revoked
  # confirmed on-chain
end
```
